# 杭州特耐时库存系统 ECS 上线、权限与备份设计

日期：2026-08-11

## 目标

将当前 `backend` 项目部署到阿里云中国内地 ECS，并在 ICP 备案期间完成私有测试。备案通过后，使用正式 HTTPS 域名提供老板 PC 后台和员工微信小程序服务。

系统必须满足以下边界：

- 老板可以在公司、家中或出差途中使用 PC 后台。
- PC 后台中的图纸、Excel、报表、员工管理和完整操作日志仅老板可访问。
- 员工通过微信小程序使用当前已有的全部功能；所有员工权限一致。
- PC 与小程序连接同一个 FastAPI 后端和同一个 SQLite 数据库。
- 员工无法通过直接调用接口绕过页面限制访问图纸或后台管理功能。
- 数据库和上传文件每天自动备份，且备份经过恢复验证。

## 已选方案

采用 ECS 原生部署加 SQLite，暂不引入 Docker 或阿里云 RDS。

选择该方案是因为当前项目已经使用 Python 虚拟环境、FastAPI 和 SQLite，原生部署改动最小，便于排查问题，也适合当前少量内部用户。未来出现较高并发写入、需要多台应用服务器或需要数据库高可用时，再评估迁移到阿里云 RDS。

## 总体架构

正式环境的数据流为：

```text
老板浏览器 ──HTTPS──┐
                    ├─→ Nginx ─→ FastAPI ─→ SQLite
员工微信小程序 ─HTTPS┘
```

组件职责：

- Nginx：终止 HTTPS、转发请求、限制请求大小和基础访问频率。
- FastAPI：业务逻辑、身份验证、权限校验、操作审计和数据库访问。
- systemd：管理 FastAPI 进程，实现开机启动、异常重启和日志收集。
- SQLite：保存员工、图纸、库存、批次、流水和系统配置等结构化数据。
- ECS 文件备份：保存已经安全生成的 SQLite 备份、上传文件和必要配置。

FastAPI 只监听 `127.0.0.1:8000`。公网只开放 Nginx 的 HTTPS 端口 `443`；FastAPI 的端口不直接暴露。

## 服务器目录

生产环境使用固定目录，代码与业务数据分离：

```text
/srv/tenaishi/app/          项目代码
/srv/tenaishi/data/         SQLite 数据库、上传文件和持久化业务数据
/srv/tenaishi/backups/      安全生成的数据库备份
/etc/tenaishi/              生产环境配置和密钥
```

代码更新不得覆盖 `/srv/tenaishi/data/`、`/srv/tenaishi/backups/` 或 `/etc/tenaishi/`。

## ICP 备案期间

备案通过前不将正式域名解析到 ECS，不公开网站或 API，也不向公网开放 Nginx 的 80、443 或 FastAPI 的 8000 端口。

私有测试方式：

- PC 后台通过 SSH 隧道访问 ECS 内部服务。
- 小程序继续使用微信开发者工具或厂内局域网联调。
- 测试阶段使用测试数据；正式数据导入前必须完成备份恢复演练。

## ICP 备案通过后

上线顺序：

1. 配置正式域名解析。
2. 申请并安装 HTTPS 证书。
3. 开放公网 `443`，保持 `8000` 仅本机可访问。
4. 配置微信小程序服务器合法域名。
5. 完成小程序备案、隐私保护指引和微信审核。
6. 网站展示 ICP 备案号，并按要求办理公安联网备案。

## 老板 PC 登录

老板使用独立账号和密码登录 PC 后台。

- 密码使用可靠的密码哈希算法保存，不保存明文。
- 登录成功后使用 `HttpOnly`、`Secure` 和适当 `SameSite` 属性的 Cookie 维持会话。
- 老板远程登录增加身份验证器动态验证码。
- 连续登录失败触发限速和暂时锁定。
- 会话支持主动退出和服务端撤销。
- 图纸、Excel、报表、员工管理和完整操作日志仅老板角色可访问。

## 员工小程序登录

员工账号由老板在 PC 后台创建。首次绑定流程为：

```text
老板创建员工并生成一次性激活码
→ 员工在小程序输入工号和激活码
→ 小程序调用微信登录
→ 后端通过微信接口验证身份
→ 后端将 OpenID 绑定到员工账号
→ 后端签发员工会话
```

规则：

- 激活码只能使用一次，使用后立即失效。
- 微信 `AppSecret` 只保存在 ECS 的生产配置中，不写入小程序或 Git。
- 员工后续通过微信身份登录，不使用共享访问令牌。
- 老板禁用员工后，服务端立即拒绝该员工现有会话和后续请求。
- 更换微信时，老板先解除绑定，再生成新的激活码。
- 所有员工权限相同，保留当前小程序已有的计划、材料、成品、库存、批次、入库、出库、流水和撤销等功能。
- 正式版本使用固定 HTTPS API 域名；当前局域网连接二维码仅保留给开发或诊断场景。

## 后端权限边界

权限控制必须在后端执行，不能只依赖页面隐藏。

- 老板：PC 后台和全部业务接口。
- 员工：当前小程序所需业务接口。
- 图纸上传、图纸文件读取、识别与确认、PC 管理页面、Excel、完整报表及员工管理接口：仅老板。
- 未登录请求返回 `401`。
- 已登录但权限不足的请求返回 `403`。
- 被禁用员工的会话不得继续使用。

入库、出库、撤销、规格修改和其他库存写操作记录操作人、时间、业务对象、结果及请求编号。继续使用现有 `client_request_id` 防重复提交机制；同一请求编号不得用于不同负载。

## SQLite 运行策略

- 使用 WAL 模式改善读取与写入并发。
- 设置合理的 busy timeout，避免短暂写锁直接导致失败。
- FastAPI 初期使用单个应用进程，避免多个进程争抢同一个 SQLite 文件。
- 每个写操作使用明确事务；失败时完整回滚。
- 数据库结构更新通过可重复执行的迁移脚本完成，不删除现有业务数据。
- 若未来出现持续写锁、高并发或多实例需求，再迁移到 RDS。

## 自动备份

每天凌晨执行以下流程：

```text
02:00 使用 SQLite 在线备份机制生成一致性数据库副本
→ 对副本执行完整性检查
→ 保存到 /srv/tenaishi/backups/日期时间/
→ 由 ECS 文件备份保存至云端
```

备份范围：

- SQLite 一致性数据库副本。
- 上传的 DXF 图纸和必要附件。
- 恢复服务所需的生产配置；密钥备份必须保持受控访问。
- 代码由 Git 保存，不在业务备份中重复保存。
- 可重新生成的预览图、二维码和 Python 虚拟环境不作为关键备份。

保留策略：

- ECS 本地保留最近 7 天数据库备份。
- 阿里云文件备份保留最近 30 天。
- 每次代码更新前额外生成一次一致性数据库备份。
- 备份失败必须返回非零状态并写入系统日志，便于监控告警。

现有 `scripts/backup.sh` 直接复制运行中的 `app.db`，不能作为正式在线备份实现。正式实现改用 Python `sqlite3.Connection.backup` 或等价的 SQLite 在线备份接口。

## 恢复流程

发生数据库损坏、误操作或服务器故障时：

1. 暂停库存写操作。
2. 停止 FastAPI 服务。
3. 选择目标日期的数据库备份和对应上传文件。
4. 将现有数据目录另行保存，避免覆盖最后现场。
5. 恢复数据库和上传文件。
6. 对恢复数据库执行完整性检查。
7. 启动服务。
8. 抽查商品、库存、批次和最近流水。
9. 确认无误后恢复员工操作。

每月至少在临时目录执行一次恢复演练。恢复演练不得覆盖正式数据库。

## 错误处理与审计

- 登录失败不暴露账号是否存在。
- 微信身份交换失败返回可理解的重试提示，不记录完整敏感凭证。
- 数据库写入失败时回滚事务，并保留错误日志和请求编号。
- 客户端遇到网络响应不确定时重试原 `client_request_id`，服务端返回首次执行结果。
- 备份、恢复、员工创建、禁用、解绑以及老板登录产生审计记录。
- 日志不得记录密码、激活码、微信 `AppSecret`、完整会话令牌或其他密钥。

## 验证与验收

实现完成后必须验证：

1. 老板可以通过 PC 登录并使用全部后台功能。
2. 员工可以首次激活、绑定微信并再次登录。
3. 员工保留当前小程序全部业务功能。
4. 员工访问 PC 后台、图纸文件或老板接口时收到 `403`。
5. 禁用员工后，其现有小程序会话立即无法执行请求。
6. 重复提交同一个库存请求不会产生重复流水。
7. SQLite 写入失败不会产生部分业务数据。
8. 自动备份按计划生成且完整性检查通过。
9. 从备份恢复到临时目录后可以读取库存和流水。
10. ECS 重启后 FastAPI 和 Nginx 自动恢复运行。
11. 公网不能直接访问 FastAPI 的 `8000` 端口。
12. 现有自动化测试及新增权限、备份和恢复测试全部通过。

## 不在本阶段实施

- Docker 容器化。
- 迁移至阿里云 RDS。
- 多台应用服务器或负载均衡。
- 员工多角色分级；本阶段所有员工权限相同。
- 改变当前小程序的业务功能范围。
