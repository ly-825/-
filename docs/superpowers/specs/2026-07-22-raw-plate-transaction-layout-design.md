# 板料流水可读性改造设计

## 背景与问题

当前板料流水把 13 个字段放在同一张横向表格中。即使设置表格最小宽度，批次、尺寸、备注、时间和撤回表单仍会争抢空间，用户需要横向滚动才能读取一条完整流水。旧库存记录的尺寸还可能直接显示为“长×宽×厚”，与当前板料统一采用的“厚度×宽×长”规则不一致。

本次只改板料流水页面的展示结构，不调整库存、流水、撤回逻辑或数据库结构。

## 设计目标

- 桌面端无需横向滚动即可读完一条流水。
- 关键信息按使用优先级排列，不再平均分配成 13 列。
- 所有尺寸统一显示为“厚度×宽×长mm”，厚度保留一位小数。
- 长备注完整换行显示，不截断、不挤压其他字段。
- 撤回功能保持原有业务规则，并与对应流水清楚关联。
- 窄屏自动纵向排列，输入框和按钮不溢出记录区域。

## 页面结构

搜索区和页面顶部操作入口保持不变。原来的宽表格替换为流水记录列表，每条流水使用一个语义化的 `article` 记录块。

### 第一行：核心流水信息

按以下顺序展示：

1. 入库、出库或撤回类型标识。
2. 批次编号。
3. 材质。
4. 标准尺寸，格式为“厚度×宽×长mm”。
5. 本次变动数量。
6. 库存变化，合并显示为“操作前 → 操作后”。
7. 流水时间。

入库、出库和撤回使用文本清晰、对比足够的状态标识，但不依赖颜色作为唯一识别方式。

### 第二行：辅助信息

依次展示库位、客户/去向、操作人和备注。字段名称始终可见，空值统一显示“—”。备注占据剩余宽度并允许自然换行。

### 撤回区

只有仍可撤回的入库或出库流水显示撤回区。桌面端位于记录右侧，窄屏时移动到记录底部。操作人和撤回原因输入框带明确标签或辅助文本，撤回按钮保持现有提交地址和后端校验逻辑。

## 尺寸显示规则

页面不再直接使用历史 `usable_size` 文本作为最终显示值，而是优先根据库存记录的结构化字段生成：

```text
厚度×宽×长度mm
```

例如长度 1450、宽度 145、厚度 1.2 显示为 `1.2×145×1450mm`。厚度调用现有钢板格式化函数，固定显示一位小数；长度和宽度去除无意义的末尾零。只有结构化尺寸缺失时才回退到旧文本，避免历史异常数据完全无法识别。

## 响应式布局

- 宽屏使用 CSS Grid，使核心信息、辅助信息和撤回操作保持稳定对齐。
- 中等宽度下时间和库存变化自动换到下一网格行。
- 窄屏改为单列或双列，批次与备注占满整行。
- 列表容器允许纵向滚动，但不设置横向表格最小宽度。
- 数量和库存变化启用等宽数字，便于比较。

## 数据与错误处理

页面继续读取 `InventoryTransactionRecord` 与对应的 `MaterialInventory`，查询、筛选和最多 500 条限制保持不变。缺失库存关联的流水仍跳过；空字段统一显示“—”。撤回继续调用现有服务，错误状态和重定向行为不变。

## 测试与验收

自动化测试应验证：

- 页面不再渲染 `wide-transaction-table`。
- 每条流水渲染独立记录块。
- 尺寸按厚度、宽度、长度生成，例如 `2.3×145×1140mm`。
- 库存变化合并显示，例如 `0 → 200`。
- 长备注位于可换行的独立区域。
- 可撤回流水仍包含操作人、撤回原因和撤回按钮。

浏览器验收覆盖桌面和窄屏：页面不得出现横向滚动；批次、尺寸、数量、库存变化、备注和撤回控件均需完整可见。

## 非目标

- 不改变流水数据结构、查询条件、导出格式或撤回业务规则。
- 不同时重做纸材、成品或余料流水页面。
- 不引入新的前端框架或第三方样式库。
